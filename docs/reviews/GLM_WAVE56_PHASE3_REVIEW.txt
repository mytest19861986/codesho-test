ADVISORIES (non-blocking — hardening pass, not a migration gate)
A1. Lock nuance: CREATE TABLE ... REFERENCES installs RI cascade triggers on Tenant/
    User, taking a brief SHARE ROW EXCLUSIVE on referenced tables (ms-scale; reads
    unaffected; NOT ACCESS EXCLUSIVE). Execute in a low-write window to avoid
    lock-queue amplification behind long-running transactions.
A2. If "one active project per learner" is a domain invariant, enforce it with a
    partial unique index (tenant_id, learner_id) WHERE is_active; otherwise document
    app-level enforcement explicitly.
A3. InterventionFeedback immutability should be enforced at the storage boundary
    (REVOKE UPDATE/DELETE or guard trigger). App-layer-only append-only is
    insufficient to sustain an audit-grade claim.
A4. MentorIntervention.status: add DB-level CHECK/enum; define whether RESOLVED is
    reopenable and whether a CANCELLED terminal path is required.
A5. ParentBridge: confirm (a) transform is explicit curation — raw mentor notes must
    not project to parents; (b) projection remains rebuildable and non-authoritative;
    (c) sync mechanism documented (event-driven vs. on-read materialization).
A6. Tier-3 rollback (migrate zero) is data-destructive — acceptable pre-GA only.
    Mark module forward-only once production data accumulates.
A7. Add an explicit cross-tenant student_code collision test to the isolation suite.
